# Budget Tracking

A responsive personal budget tracker with monthly income and expenses, spending categories, budget limits, transaction search, deletion, and CSV export.

## Development

Requires Node.js 20.19+ or 22.12+.

```sh
npm ci
node scripts/sync-sheet.mjs
npm run dev
```

Run `npm test` for calculation and validation tests, and `npm run build` for a production build. `npm run preview` serves the built application.

If Google is blocked in the development environment, download the most recent deployed snapshot instead: `curl --fail --location https://nakkasandeepgoud.github.io/Budget-Tracking/shared-data.json --output public/shared-data.json`. The generated snapshot is ignored by Git; shared-data updates are published only to `gh-pages` by the sync workflow.

Data is stored in this browser's local storage. No login, server database, or synchronization is included. CSV export downloads the selected month's transactions. Changing currency changes formatting only; it does not convert amounts. Web fonts are optional; the interface falls back to system fonts offline.

## Importing an application database

Use **Upload Excel / JSON** to select a Durgamatha `.xlsx` workbook with `Expenses` and `Member Funds` sheets, or a `budget-tracking-database-v1` JSON file. Imports are processed privately in the current browser; the file is not sent to a server. Reimporting replaces the source snapshot and its generated transactions, preserving manually entered transactions. Only paid expense amounts enter transaction totals; unpaid balances, payer, funding source, remarks, reimbursement amounts, due dates, and member records remain available in the source snapshot panel. Opening funds and undated member cash contributions use the reporting month's first day, explicitly labeled as an assumption. The snapshot panel does not change when you edit the separate transaction ledger. Database backup exports the source snapshot.

Excel imports preserve the workbook's advance formula: all payments attributed to each member, less reimbursements. This includes collected-fund payments and can double-count liabilities. PDF-derived JSON uses the Personal Advance-only rule instead. The source panel labels the active rule. Recalculate and save formula results in Excel before importing. The Excel reader loads only when an Excel file is selected.

## Deployment

GitHub Pages serves the `gh-pages` branch at its root. The workflow tests the app, reads the configured public Google Sheet, builds the site, updates that branch, and requests a Pages build. It runs on pushes to `main`, manual dispatch, and a 15-minute schedule (GitHub can delay scheduled runs). Keep **Deploy from a branch → gh-pages → / (root)** selected in Pages settings. The production build uses `/Budget-Tracking/` as its asset base.

## Shared Google Sheets data

Upload the Excel workbook to Google Drive and open it with Google Sheets. Preserve the `Expenses` and `Member Funds` sheets and their input column names. The current static site can only read a Sheet that permits unauthenticated viewing. Select **Anyone with the link → Viewer** only if those financial records may be public. Do not grant editing permission to visitors.

The configured Durgamatha Google Sheet uses the application database format: `Expenses` (`id`, `date`, `description`, `total`, `paid`, `payer`, `source`), `Members` (`id`, `name`, `annual`, `cash`, `sponsor`), and `Settings` (an `Opening fund` key and numeric value). This format uses the Personal Advance-only rule. The Excel workbook format remains supported separately.

The ordinary app URL loads a shared snapshot from `shared-data.json`, generated by `scripts/sync-sheet.mjs` from `public/shared-source.json`. This avoids cross-origin Google downloads in visitors' browsers. Update records in Google Sheets and wait for the next successful synchronization before refreshing; application edits are not written back to Google. A failed sync stops publication and retains the last deployed snapshot. The Google Sheet URL and shared financial snapshot are public. Never put credentials in the configuration. A private Sheet requires a backend and Google authentication, which are not configured here.

## Two-way synchronization

The authenticated writer is prepared in [google-apps-script/Code.gs](google-apps-script/Code.gs). Activate it by following [google-apps-script/SETUP.md](google-apps-script/SETUP.md), then add the deployed `/exec` URL as `apiUrl` in `public/shared-source.json` and publish. Until an API URL is configured, the website remains read-only; no real Google write has been verified yet.

With the writer configured, viewers read the live Sheet and refresh about every 30 seconds. Editors unlock the app using the owner-generated editor key. That key is kept in tab memory, never configuration or browser storage. Expenses, other income, member contributions, opening fund and budgets can then be saved through the app. Changes appear only after the server confirms them; invalid, unauthorized and conflicting writes are rejected. The scheduled export preserves the `Transactions` and `Budgets` tabs as well as the original records. If the live endpoint fails during startup, the app falls back to the latest published snapshot in read-only mode.

**Connect Google Sheet** provides an optional direct-view URL containing a different Sheet ID; this mode relies on Google's cross-origin XLSX export. The default dashboard uses the scheduled same-origin snapshot instead. **Copy shared link** preserves whichever mode is active. Tests cover workbook parsing, validation, sign-in response rejection, and simulated direct and snapshot loading. Verify the real synchronization workflow and the deployed snapshot before claiming a live connection works.
